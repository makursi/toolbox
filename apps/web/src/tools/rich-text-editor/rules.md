# rich-text-editor · 设计规则（工具级）

> **管什么**：这个 Tool 自己的设计规则与词汇——页面结构、文档模型、两个占位符、可访问名与命中区。**只约束 rich-text-editor；站点级规则**（外壳、设计语言、CSP、门禁量具、Tool 契约）在 `apps/web/docs/design.md` 与 `apps/web/docs/design/`，两者不互相重复。站点文档只装站点级规则，一个工具的私有规则住在这里，见 `docs/adr/0014-tool-scoped-rules-live-with-the-tool.md`。**和它一起读**：`README.md`（怎么工作、手工清单）、`docs/agents/design-notes.md`（这棵树为什么这样长）、issue #205（spec）与 #206（本片）。

## 词汇

站点术语表（`CONTEXT.md`）只定义站点词；下面几个是本工具的领域词，本站其它文档不继承它们的含义：

- **文档（document）**：一次编辑的全部内容。规范形式是 ProseMirror JSON；标题块是它的第一个节点，正文段接在后面。
- **画布（canvas）**：文档的编辑区，一块约 **720px** 的阅读度量。标题就是它的第一行，没有第二个标题输入框。
- **标题块（title block）**：文档的第一个节点，一个 H1。它在页面里是画布的第一行，在导出文件里是文档标题。
- **正文段（body paragraph）**：标题块之后的段落；一次回车产生一个新的段落。

## 页面结构

- 本页是**外壳 + 一块画布**（#206）：返回首页、标题「富文本编辑器」、描述与 `metadata` 来自站点级 `ToolPage` 外壳（`src/components/tool-page/`），不在本文件职权内；外壳下面只有一个元素是本页自己的，也就是画布。
- 画布是 720px 的阅读度量，在 960px 内容列里居中，离标题块 `mt-10 sm:mt-12`（工具页正文与标题的距离），发丝边框、8px 圆角、画布色底、20px 内距。`data-slot="rich-text-canvas"` 是它的指纹锚点。
- **还没有工具栏**，也没有斜杠菜单、Markdown 输入规则、浮动工具栏、自动保存、导入导出与封面：那些是 #207–#212。它们落地时，工具栏行、保存状态与文件菜单才是这一页的控件；本片常驻的控件只有外壳自己的两个（配色开关与返回首页）。
- 画布的高度是 `60vh` 的编辑面：空文档只有两行字，而一个访客要在两行字下面点击时仍然落在编辑面里。

## 文档模型

- **规范文档是 ProseMirror JSON**。Markdown 与 HTML 都是导出时从它派生出来的，不是源（#205 的 Implementation Decisions）。
- 初始文档是**两个空节点**：一个 H1 标题块与一个段落。它不是 props、也不是 React state：这个组件是这个页面唯一的消费者，页面没有第二种内容来源。
- **还没有持久化**：重新加载页面得到一份新的空文档，这是本片的现状而不是缺陷；草稿存进 IndexedDB 是后续的票。
- 编辑器**只在客户端创建**（`immediatelyRender: false`）。服务端只发出一个空的画布，编辑器的内容不进服务端 HTML：服务端不可能知道访客还没打的字，而把一份 contenteditable 渲染到服务端再让水合去对账，正是光标丢失的那类 bug。
- 组件自己收着文档，没有从 props 重新灌入内容的路径，所以页面重渲染不会重置它——门禁读的就是这一条。

## 占位符

- 空标题块显示「无标题」；文档的**第一个正文块**（初始文档里的那一段）显示「开始写吧，输入 `/` 插入内容」。两句原文在 `RichTextEditor.tsx` 的常量里，门禁读的是**画出来的** `::before` 内容，不是 DOM 文本。
- 正文那句**只挂在文档的第一个正文块上**，不是挂在每个空段落上：它说的是「这份文档还是空的」，而访客按回车造出来的空行不是再开始写一遍的地方。空行因此不画占位符。
- 两个占位符**同时**显示（Placeholder 的 `showOnlyCurrent: false`）：标题是一个独立的空块，正文正在被写的时候，标题仍然是空的，所以标题的句子不能藏起来。
- 正文段的**第一次击键**让它的占位符消失；标题的占位符留到标题自己被写为止。这不是一条「空态」开关，而是两个空块各自的状态。
- 占位符是 CSS 的 `::before` + `content: attr(data-placeholder)`，不是文案节点：它进不了选区、不属于文档、也不会被导出。颜色取占位符 token（`--site-placeholder`），实测对比度在 `apps/web/docs/design/colour.md` 的表里。
- 标题占位符的字号跟着标题块走（34px / 1.3），所以「无标题」读起来就是标题，而不是一行小字。

## 可访问名与命中区

- 编辑面的无障碍名是「文档内容」（`aria-label`）。编辑器元素的角色是 TipTap 自己写的 `textbox`，所以读屏读到的是「文档内容，可编辑文本」而不是一个匿名的输入区。
- **画布不带 `.touch-target`**：它不是一个小可点控件，而是编辑面本身，命中区就是整块 720px 阅读度量。给它挂伪元素遮罩会把一层东西盖在文本上，而平台自己的内层命中（这里是光标放置）正是 `#172` 的 range 滑块丢掉的那一半。这一页的 44px 控件因此只有外壳的配色开关与返回入口。
- 编辑面自己**不画焦点环**：编辑面拿到焦点时，画布那条发丝线换成 ink（卡片上的 `focus-within:border-ring`），也就是站点「选中只换线、不换色」的那条规矩（格式卡是同一种写法）。焦点色仍是站点的 ink，不是浏览器默认的高亮蓝；而 2px 的环会在这张卡里再画一个方框，线本身已经是访客读到的边界。

## 量具

- **指纹（`ui-fingerprint.mjs`）按页声明**外壳的四个锚点、`tool-page` 与 `rich-text-canvas`。标题块与正文段是 ProseMirror 自己生成的子节点，挂不了 `data-slot`，所以被锚定的是包住它们的这张画布——它正是本页唯一一块会因为本页的改动而移动的区域。
- **命中区量具（`touch-targets.mjs`）按名字声明本页的常驻控件**：`切换到` 与 `返回首页`。画布不是 `.touch-target`，理由见上一节；工具栏落地时，每个新控件在自己的票里进这份清单。
- 两个占位符是画出来的句子，不是控件，没有名字可以声明；它们由门禁读 `::before` 的内容来盯住。
