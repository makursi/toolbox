         **一条自己挖出来又当场修掉的缺陷（#92 要的那一半）**：预览的 `sticky` 原本挂在画布列**里面**那层包着预览框的 div 上。sticky 元素只能在**自己的包含块**里移动，那层 div 的包含块是画布列，而画布列的高度正好等于预览框——所以它**一寸都动不了**：滚到页面底部时预览框的 `top` 是 −444.9，与静态元素无异。也就是说 `rules.md` 里「窄屏预览置顶（sticky）」描述的是一个从未生效的意图，拖滑块时其实看不见画面。修法是把 `sticky top-4` 挪到**画布列自己**身上（包含块变成横跨两列的那个 Flex），并给画布列 `z-[2]`（它会盖住跟在后面的配置列）；标签行的窄屏偏移于是按规格回到「预览实际高度 + 间距」，高度由组件**已经持有的缩放系数**换算成 `--cover-preview-height`（取整到整像素，因为它决定一行整像素落在哪儿）。量具因此新增两条更硬的读数：**滚到面板中段**时预览框仍钉在顶部（`top` ≈ 16）且标签行在它下方不重叠——旧的那条只在页面底部读一次，那时预览早已离场，**根本守不住「两者不重叠」**；以及在**默认比例**上再读一次预览框，因为封顶是窄屏专属，宽屏要能同时证 16:9 与 1:1 都不受它影响。

**仍未做的**：`package.json` 的堆栈仍会被顶层未处理拒绝打印出来（`connect` / `navigate` 抛出后没人接），读起来不如 #99 想要的那样干净；按票的边界这一轮没修。T4/T5 的**源码级红一次**（摘掉 `.cover-icon-option`、把 `keepMounted` 放回去）仍未做——它们的路线已写在每条 claim 的 `falsification.source` 里，但还没在临时分支上跑过。`column-order` 与 `preview-default-ratio` 两条注入的 `case`（1024 宽那档）是**推断**而非先量后写，欠着 #96 第十九轮「每条 case 先量后写」那条规矩。3. **要不要把浏览器检查做成仓里的东西**（所属：站点级 · 内容：量具与门禁分层决策 · 时间：2026-09-17 两次否决 – 2026-09-20 门禁落地，ADR-0012）**：**上面那五项（可访问名字、四种格式的端到端、动效、reduced-motion、Lighthouse）现在属于「一次性的证据」，靠一段没进仓的脚本得到。它这一轮抓到了一个真实缺陷（`.lift` 漏在 reduced-motion 门控外，审计不会报，只有真的去模拟 reduce 才看得出来）。值不值得因此引入一个浏览器测试依赖（比如 Playwright）、并给它一个 CI 作业，是一个要单独决定的事，别顺手加。**2026-09-17（第五轮）又否了一次**：那一轮修的是只有鼠标才发现得了的缺陷，是最像引入浏览器的理由，选择仍然是把陷阱写进注释、`AGENTS.md` 与手工清单（见第五轮），所以这条继续开着。
**2026-09-17 已按最小口径落地一部分**：`apps/web/scripts/ui-fingerprint.mjs`（`pnpm --filter @toolbox/web fingerprint capture|compare`）进了仓，只做两件事——把三个页面 × 5 个宽度 × 2 套配色抓成一份指纹（正文、链接、带几何与 Mantine 类名的 DOM 大纲、关键计算样式），再比对两份。它堵的是这类改动唯一说不清的问题：「只是搬家，界面一个字没变」。当时仍然**不进 CI**（CI 里没有浏览器），也**不引入 Playwright**：指针、键盘、端到端转换依旧是一次性脚本，结论记在本节。要扩这个脚本之前先问一句——只用 CDP 与 `node:` 内置模块能不能做到？能，就不加依赖。
**2026-09-20 又进了一个，同一个口径**：`apps/web/scripts/touch-targets.mjs`（`pnpm --filter @toolbox/web touch-targets`）。issue #29 要的正是一个只看得见渲染结果的量（声明在那儿、命中区域不在），而它又不是一次性脚本能收尾的事——下一改就可能再有人给某个自带 `overflow: hidden` 的 Mantine 控件挂上 `.touch-target`。做法是从每个控件的中心逐像素向外问 `elementFromPoint`，**两侧都要答**才算数（所以「靶子长大盖住邻居」也会读成不达标），360 / 390 / 768 / 1024 × 两套配色，并且数一遍每页该有几个控件——一个什么都没量到的探针会「通过」，那是这个检查唯一能骗人的地方。它当时仍然不进 CI、不加依赖：CDP 加 `node:` 内置模块就够了，「不加依赖行不行」这个问句这次的答案同样是可以。两个脚本共用的那条 CDP 连接抽在 `apps/web/scripts/cdp.mjs`。
**2026-09-20 当天又定了一次，这次是反着的**：上面那条规矩只继续管**量具**，浏览器这一层另外立了一个**门禁**——`apps/web/e2e/` 加 `@playwright/test`（`pnpm e2e`；Turborepo 里 `e2e` 依赖 `build`，CI 里是独立一步，跑的是 `pnpm build && pnpm start` 的生产构建）。理由不是「CDP 做不到」——恰恰相反，第一版要买的三件事（真鼠标点格式行、一次转换出五种格式并解码回来、零外发请求与零 console 报错）在上面九轮里全都用 CDP 做过，所以**「能力」那一列是空的**；缺的是**形式**：那九轮的脚本是一次性的、没进仓（原文：「要重复就得再写一遍」），而 `touch-targets.mjs` 已经证明了另一半——一个没人记得跑的检查等于不存在。于是分界定成一句话：**量具管几何与计算样式（本地、同一台机器测两次），门禁管行为（每次改动、跑在 CI、红了挡 PR）**。落到文件上是：几何类的断言（44px、有没有移动）留在 `scripts/`，行为类的断言（点下去有没有反应、文件进得去出得来）进 `e2e/`；两边都说得通时归 `scripts/`，因为几何要的是像素而不是预期值。代价照实记：机器上多一份 Playwright 钉死的 Chrome for Testing（153，正好和量具量过的那个大版本同一档），`pnpm install` 不会下它、要单独 `playwright install chromium`，CI 多一步加一个按 Playwright 版本做 key 的缓存。**红一次的证据**：把 issue #29 那个 bug（`.touch-target` 挂回格式行的根 `<div>`）注回生产构建，10 个格式行用例（5 格式 × 2 宽度）全红，拿掉即全绿——守卫证明过自己能失败。决定记在 `docs/adr/0012-playwright-for-the-browser-gate.md`。
