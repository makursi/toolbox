# 布局

> **管什么**：列宽、内距、页面节奏、断点（两个 `sm` 不是一回事）、窄屏回退。**和它一起读**：`apps/web/docs/design/components.md`（窄屏上各控件长什么样）。

- 内容列宽 **960px**，两种写法：旧层是 Mantine 的 `Container size="md"`，新层是 `mx-auto w-full max-w-[960px] px-4`（工具页外壳自 #132、**页头/页脚/404 自 #163**、**image-converter 整页自 #164–#166、首页自 #167** 都是新层这一种；数值是这条规则，写法随页）。**自 #167 起没有任何页面在用旧层那一种写法了**，它留在文档里是因为 #168 之前那条 `@import` 还在。
- 页面内距：首页 `py-12 sm:py-24`，工具页与 404 页 `py-10 sm:py-16`。
- 这些**写成 Tailwind 工具类**：`utilities` 层在 `globals.css` 里排在 `mantine` 之后，所以工具类能稳定覆盖 Mantine 的默认值。这也是 ADR-0006 之后 Tailwind 仍然留在 App 里的理由。
  注意一个容易说错的细节：`gap` 只接受 spacing 值，**不接受断点对象**；但 `py` 是 `StyleProp`，**接受**（Mantine 会生成 `@media (min-width: …)`）。两种写法都能达到目的，这里选工具类是为了让响应式规则集中在一处。
- 首页节奏：标题块与工具列表之间 `gap-10 sm:gap-14`；工具页正文在标题下方 `mt-10 sm:mt-12`。
- **首页卡片是网格**：**640px**（Tailwind 的 `sm`）以上两列，以下整行堆叠，一个 Tool 一个格子——只有一个 Tool 时网格会留出一个空格子，那看起来像布局出错而不是留白，所以第二个 Tool 落地那天才从堆叠改过来（2026-09-25，PR #62；经过在 `apps/web/docs/design/log.md` 第 5 条）。形状规则：有几个内容就几个格子，不要为了凑行留空格子。**这句话以前写的是 768px，那是本站的 `sm`、不是这个类拼出来的那个**（#167 量过：类一直是 `sm:grid-cols-2`，也就是 640px）。
- **外壳**：页面内容包在 `<main>` 里，外面是一层 `min-h-[100dvh]` 的纵向 flex（内容 `flex-1`，页脚在最后）。页脚因此在短页面（首页、404）上贴在视口底边，而不是浮在半空；用 `min-h` 而不是固定高度，因为工具页比视口长，必须照旧滚动。
- 任何多列布局都必须在同一个组件里声明窄屏回退（新层是 `flex-col-reverse md:flex-row`、`w-full md:w-[220px]`；旧层是 `direction={{ base: "column", sm: "row" }}`、`w={{ base: "100%", sm: 220 }}`）。**同一个元素上互相牵制的响应式属性必须来自同一套断点**（方向、对齐、顺序、宽度算一处）：封面生成器一度用 Tailwind 的 `items-start` 配 Mantine 的 `md`（992px），768–991 这一档方向还是 column、对齐却已回到 `flex-start`，画布列于是按内容宽 1280px 撑开、预览不再缩放（2026-09-30 量到 545px 横向溢出；同一处最早的写法在 360px 下溢出 938px）。**写法跟着层走，数字不跟着走**：旧层里这类改动写成 Mantine 的响应式属性（`align={{ base: "stretch", sm: "flex-start" }}` 与 `direction` 天然同源），新层里两边都写成工具类、而本项目的 768 在新层拼作 `md:`（48rem）——两套拼法都不能在同一处混用。组件里其它元素各自用所在层的断点即可，宽度可以不同（封面生成器的两个文字输入框就是在 `md` 上并排的），但同一个元素上不要混两套。
- **宽度只交给响应式属性或响应式工具类，不要写进 `style`。** `style` 生成的是行内声明，会压过任何断点里的类，于是那个元素在**所有**宽度上都取同一个值。"预留框图把文字挤成竖排窄条"就是这么来的：`w={{ base: "100%", sm: 220 }}` 旁边多写了一个 `style={{ width: "100%" }}`，断点从来没生效过。工具卡片自 #163 起把这一条写成 `w-full md:w-[220px]`，正是同一个理由的另一半：宽度是那个框唯一需要响应的部分。
- **行内声明压过一切：简单 style prop 也是行内。** `p="lg"`、`mt="md"` 这类单值会写成 `style`，所以它们**无法**被任何 `@layer` 里的规则覆盖（做触屏适配时撞过这个）；而带断点对象的响应式属性（`w={{ base, sm }}`）生成的是**类**，可以被覆盖。需要留出覆盖余地的尺寸就写成类（如 `.dropzone-pad`）。
- **本项目的 `sm` 是 768px。** Mantine 的断点是 `em` 单位（`sm: 48em`），Tailwind 的 `sm:` 是 640px。同一个词在两个体系里不等值，所以"在 `sm` 以上变成两列"这句话必须先说清是哪一个 `sm`。**新层里这个 768 拼作 `md:`**（48rem）：`sm:` 会早 128px 翻转，而 768–767 这条带里方向与对齐一旦来自两套断点就会错位（上面那条 938px 溢出就是这么来的）。
- **「窄屏」与「触屏」是两件事，别合并成一个"移动端"。** 窄屏是宽度（`max-width: 640px`，Tailwind 的 `sm` 以下）；触屏是指针能力（`@media (hover: none)`）。同一个 360px 宽的手机两个都命中，但一个窄窗口的桌面**只命中窄屏**——而它照样能把文件拖进来。所以：去掉拖拽区用触屏条件，按钮占满一行用窄屏条件（见 `apps/web/docs/design/components.md`）。
