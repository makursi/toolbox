# 组件

> **管什么**：逐组件的外观与行为规则，含触控目标、图标与禁用态。**和它一起读**：`apps/web/docs/design/colour.md`（勾选态只换发丝颜色、配色开关）、`apps/web/docs/design/layout.md`（`sm` 到底是哪一个）、`apps/web/docs/design/assets.md`（封面例外）。

- **卡片**：`Paper withBorder`——发丝线来自 token，绝不硬编码灰色；`radius="md"`（8px）、`p="lg"`（24px），外加一个 `lift` 类，hover 时把阴影提到 4% 不透明度、过渡 200ms。
  **没有阴影是设计本身，不是漏写的样式**——「给卡片加个阴影」是后来者最容易"顺手修"的地方，所以特意写在这里。
- **卡片在窄屏上的形状**：封面在宽屏上在左侧（220×165），在窄屏上**移到文字下方**且**高度封顶 180px**（多余的裁掉），标题同时从 18px 升到 20px。理由：手机上封面占满屏宽会把标题挤到下面、又把卡片拉得很长，而直接隐藏封面等于把这张图在手机上删掉。换序由一个属性完成：标里是 `[封面, 文字]`，`direction={{ base: "column-reverse", sm: "row" }}`。
- **圆角**：容器 8px、控件 4px（`Button` 默认 `radius="sm"`）。一套体系两个值；**药丸形主按钮被否决**——放在方正的卡片里，它读起来像装饰。新层读的是同一套：`--radius-md` = 4px（注册表组装控件时用的名字）、`--radius-lg` / `--radius-xl` = 8px（容器用的名字），理由与取舍见 `apps/web/docs/design/colour.md`。
- **按钮**：Mantine `filled`，用 `ink` 调色板（浅色接近黑、深色接近白），对比色由 Mantine 自动计算（17.33:1）。
- **图标**：来自 Phosphor，由 Iconify 的 Tailwind v4 插件在**构建期**编进 CSS（`apps/web/src/app/globals.css` 里的 `@plugin`），写成一个字面量类名 `icon-[ph--arrow-right-bold]`，绘制方式是 `currentColor` 的 mask，所以图标跟随所在文字的颜色与字号。**统一用 bold 一个字重**，尺寸就是 `1em`，没有图标专用的尺寸 token。**不做包装组件**：Tailwind 是从源码里读出类名的，拼出来的名字不会被编译，`apps/web/src/app/__tests__/icons.test.ts` 会拦下这种写法和写错的图标名。除了这三条，`.icon` 只负责插件管不到的两件事（`flex-shrink`、以及把 inline-block 的图标下移 `0.125em` 与文字对齐）。理由与取舍见 `docs/adr/0009-phosphor-icons-through-iconify.md`。
- **折叠控件（disclosure）**：目前没有在用。要不要折叠是每个工具自己的决定，按工具级规则进工具自己的文档（`docs/adr/0014-tool-scoped-rules-live-with-the-tool.md`）；image-converter 的「高级选项」2026-09-18 已删，见它的 `rules.md`。
- **Tool 页的返回入口**：标题上方一行（图标 + 返回首页，`size="sm"`、dimmed，hover 提亮到正文色，用 `.quiet-link`），箭头是 `ph--arrow-left-bold`。页头的 wordmark 也回首页，两者是有意的：一个是上下文、一个是全局。404 页不加（它已经有一个主按钮）。
- **配色开关**：页头右侧，`variant="default"` + `size="compact-sm"`，带 `.touch-target`（页头里最小的靶子也是 44×44）。**只有图标，没有可见文字**：浅色下是月亮、深色下是太阳，写的都是**将要切到的模式**。名字给读屏（「切换到深色」/「切换到浅色」），用 `sr-only` 文字写在图标旁边，两套都在 DOM 里、由样式表切换（见 `apps/web/docs/design/colour.md`）。
- **输入控件**：发丝边框；占位符与标签的对比度都按它们实际所在的表面测过；聚焦环取 ink 色。
- **404 页**（`apps/web/src/app/not-found.tsx`）：三个东西，不多不少 —— 发生了什么、为什么可能发生、一个出口。用它自己的排版站起来（`Container size="md"`、标题用 `h1`、说明用 `dimmed`、出口是一个主按钮）；**不放超大数字、不放插画、不列「你可能想找」的链接清单** —— 一个只有一个工具的站点没有那么多去处可推荐。回首页的按钮写成 `component="a"` 而不是 `component={Link}`：字符串让 Mantine 渲染成真锚点，页面因此保持 Server Component（传函数给 Client Component 会被构建拒绝），代价是一次整页加载，而对一个 404 来说这反而更稳：关掉 JavaScript 也回得去。
- **禁用的控件必须说明原因**：灰掉的按钮或输入框旁边要写清缺的是哪一步，而不是让人猜、也不是用 tooltip 藏起来。这些句子来自工具自己的纯文案层（先例：image-converter 的 `core/hints.ts`），有单测；而且必须**随状态变化**，一句通用的"请完成上面的步骤"等于没说。
- **窄屏上动作占满一行**：`.action-full-width` 在 `max-width: 640px` 生效（Tailwind 的 `sm`），主要动作按钮按此占满，理由文字换行到按钮下方。
- **触控目标 ≥44px**：视觉尺寸与可点尺寸不是一回事。`.touch-target` 用一个居中的伪元素把可点区域撑到至少 44×44，不改绘制、也不改元素自己的框；**元素自己的框小于 44px 时，得由布局另外给它 44px**——伪元素撑不出元素没有的尺寸，图标结果行就是这种情况（见下条）。**它只能挂在「自己处理点击」的元素上**（`<button>`、`<a>`、`<label for>`），挂在只负责包裹的容器上不是把靶子变大，而是把点击吃掉：伪元素收到的点击算在它所属的元素头上，而容器没有处理器，于是鼠标永远点不中、键盘却照常能用。格式行因此不用这个类，改成把它的 `<label>` 撑满整行（`.format-row`）；移除文件、配色开关、清空各自就是自己处理点击的元素，返回首页挂在 `<a>` 上而不是它里面的那个 `<p>`（伪元素的点击属于生成它的元素，「拥有者」才是规则要的东西）。主要动作按钮用 `size="md"`（42px）：Mantine 默认的 `sm` 是 36px，在触屏上偏小。**但 42 ≠ 44**：那是写明的例外，不是达标线——凡是要 44 的地方都不许拿 `size="md"` 顶替。**丢了 `.touch-target` 就是丢了整个靶子**：量具只走带这个类的控件，一个没有名字的控件一旦丢了类，就同时从点名与测量里消失，而页面一个像素都没变。所以没有名字的控件必须在 `touch-targets.mjs` 的 `carriers` 里按选择器声明（先例：封面生成器图标结果行的 `.cover-icon-option`），并且每个声明的选择器至少要命中一个元素——命中 0 个的选择器守不住任何东西，量具按失败处理（#106）。
  **伪元素会被裁：Mantine 的 `Button` 自带 `overflow: hidden`**，它把伪元素裁成按钮自己的框，于是挂在 `Button` 上的 `.touch-target` 只有声明、没有那个可点区域（2026-09-18 的绘制尺寸是 32×26 与 46×26，2026-09-20 用探针量到它们的可点区域是 31×25 与 45×27，而两者的 `::after` 一直算得出 44×44）。**2026-09-20 已修**，办法是一条带守卫的覆盖：`.touch-target.mantine-Button-root:not([data-loading]) { overflow: visible }`。守卫不是装饰：Mantine 需要那个裁切只在 loading 一个状态里（label 会向下滑出，还有一道模糊扫光会溢出），而 `loading` 同时也会 `disabled`（Mantine 的 `Button` 传的是 `disabled: disabled || loading`），所以「保留裁切的状态」正是「不能被点的状态」，其余时候遮罩逃出去。实测就是这个行为：在按钮上加上 `data-loading`，计算出的 `overflow` 从 `visible` 变回 `hidden`，去掉再变回 `visible`。`CloseButton` 不裁，从来不用管它。重量的结果（360 / 390 / 768 / 1024 四个宽度，加 375×667 一档，× 两套配色，`pnpm --filter @toolbox/web touch-targets`）全部达标；image-converter 那几个控件的逐个数在它的 `rules.md` 与 README。探针按像素中心向外走，正好 44 的量出来就是 43；它要求两侧都答得上，所以靶子长大盖住邻居也会读成不达标。**2026-09-30 复核**：上面那句「全部达标」此前对封面生成器那一页是假的——它从 #54 起就在这个脚本里红着（406 处失败），因为那时量具不进 CI、也没人跑；第十三轮修好后同一脚本 0 失败，逐条证据在 `apps/web/docs/design/log.md`。**两种指针各量一遍（#84）**：窄屏与触屏是两件事，所以 360 / 375 / 390 会各量两次——先按「窄窗口的桌面」，再按「手机」（`hover: none`、粗指针）：触屏那一支允许把控件放大（image-converter 的拖放按钮就长到 50px），所以窄窗口那支才是严格的那一遍，而 768 / 1024 只量桌面那支。
- **44px 的声明会被 flex 收缩打掉**：`.touch-target` 只把可点区域撑大，元素多高是布局说了算。封面生成器的图标结果行（`mah={220}` 的滚动栈里几十行）被 flex 收缩回最小内容高度 20px——修这一条时先只写了 `h={44}`、内联样式也是 `height: 44px`，计算值仍是 20px，因为 flex 收缩不看内联高度；让它真正立住的是再补一个 `shrink-0`。在那之前，44px 的伪元素落在 20px 的行上会被相邻行的伪元素抢走，实测可点只剩 1–3px。修法是行上 `h={44}` 加 `shrink-0`（栈照旧滚动）。两件事合起来就是 `apps/web/docs/design/log.md` 第十三轮里那 406 条失败：**声明与量出来的事实之间差的是布局**。
- **文件输入和可搜索下拉在新层上的形状**（2026-10-05，#130）：`input[type=file]` 与 `input[type=range]` 同类——**替换元素、不画 `::after`**，所以它的 44px 来自自己的 `h-11`，`.touch-target` 在它身上是量具的标记而不是遮罩；名字一律来自 `<label for>`。**可搜索的下拉用注册表的 `Popover` + `Command`**（`shadcn add popover command`），因为规则要的是**按子串过滤加自己的空态文案**，而 Radix 的 select 只有 typeahead：`shouldFilter={false}`，过滤交给工具自己的纯规则（先例：`core/fonts.ts` 的 `matchesFont`）。**触发器是一个只读的 `input`**，带 `role="combobox"`、`aria-expanded`、`aria-controls`；把同一个 role 挂到 `<button>` 上也是注册表自己的做法（它替换掉的 Radix select 就是），但本站的 a11y 规则要求这一处的触发器是**真的表单元素**，所以写成只读输入、搜索框放进弹出的列表里，并让列表打开时由 `onOpenAutoFocus` 把焦点交给它（不用 `autoFocus`，那条规则同样拒）。这一个元素上的 `jsx-a11y/prefer-tag-over-role` 按元素关掉并写明理由，而不是把语义删掉。**它的开合动画由站点关掉**：注册表给 `PopoverContent` 的 `animate-in` 是本站第一个「自己会动」的 Primitive，所以 `globals.css` 在 `prefers-reduced-motion: reduce` 下按 Primitive 自己的 `data-slot="popover-content"` 把 `animation` 取掉——写法与上面 `.reveal` / `.lift` 相反（那两条是「加动画前先问偏好」，这里是「把库给的动画去掉」），而锚点是 #126 定的那条。
- **拖放区在两种指针下是两个形状**（2026-10-05，#130；规则本身写在 `apps/web/src/app/globals.css` 的 `.dropzone-touch-flat` / `.drag-hint` / `.add-files-button`）：有指针时虚线框就是投放目标、拖拽提示也在；`hover: none` 的触屏上**没有东西可拖**，于是框与提示一起退场，里面的文件按钮成为「添加文件」的全部并长到拇指尺寸（50px）。两个方向都由量具的一条声明守着（`touch-targets.mjs` 的 `drop-zone-pointer`），而它的证伪 **必须跑在触屏那一支上**——列表里的 `touch: true` 就是为这件事加的，因为默认那支是桌面指针，在它上面证明不了 `hover: none` 的行为。
- **注册表发来的 Primitive 可以带记录过的改动**（2026-10-05，#130）：`command.tsx` 删掉了 `lucide-react`（本站图标是构建期编译的 Phosphor 字面量类，见 `docs/adr/0009-phosphor-icons-through-iconify.md`，而 `lucide-react` 根本不是依赖）与 `CommandDialog`（本站没有模态命令面板，它是唯一把生成的 `dialog.tsx` 拉进包里的东西，文件随变体一起删掉——先例是 #128 删掉那个叫不出名字的 `slider`）。改动写在文件顶部，重新生成时看得见；除此以外仍是注册表自己的代码。
- **页脚**（`src/components/site-footer/site-footer.tsx`）：发丝上边框加一行小字（`dimmed`、`size="xs"`）。只写站点真正承诺的那句话（文件只在这台设备上处理），**不复述导航**（页头已经有一份），不放第二组链接，不放版权年份。它存在的理由是让每个页面都有结尾；它就只该做这一件事。
- **锚点：`data-slot`**（`apps/web/src` 里的自有组件，2026-10-05，#114）：凡是指纹要量的区域，都在自有组件上盖一个 `data-slot="<名字>"`——页面外壳与 `<main>`（`page-shell` / `site-main`）、页头页脚、工具卡片及其封面框 / 标题 / 描述、工具页外壳（`tool-page`）、image-converter 的格式卡、封面生成器的两列 / 预览框 / 标签行 / 三个标签 / 三个面板。它是一个**锚点，不是样式、也不是行为**：加不加它，画出来的东西一个像素都不变（#114 前后、指纹未改动的 123 项读数全等）。词汇取的是新组件层自己的约定（它给每个组件盖 `data-slot`），所以迁移时两边说的是同一种话、不需要翻译表。名字要在 `apps/web/scripts/ui-fingerprint.mjs` 的 `PAGES` 里**按页声明**：命中 0 个就是失败，因为一个什么都没命中的选择器守不住任何东西，而「什么都没动」和「什么都没量」否则印出来是同一句话。没被声明的 `data-slot` 仍然会出现在大纲里，所以漏声明表现为一处差异而不是静默。理由、证据与它换来的东西见 `apps/web/docs/design/log.md` 第二十三轮。
- **新层画出来的区域标 `data-layer="primitive"`**（2026-10-05，#126）：它不是量具的锚点（那是 `data-slot` 的活）、自己也不画任何东西，只有一个地方读它——`globals.css` 在这个作用域里把 Tailwind 的 `white` 与 `black` 重指到本站的纸与墨。理由是强制项：禁纯 `#000000` / `#ffffff` 不由组件层决定，而注册表发来的组件不是我们手改的东西，它自己的变体里就写着 `text-white`。**它有作用域、不是全局**，因为 `bg-white` 在别处是正当的：封面生成器预览框画的是**导出产物的底色**，而"导出的图片像素不算"正是颜色规则早已记下的例外——全局重指会让访客下载到的文件变一个颜色。
- **两套样式之间那条线：什么算"库的补丁"、什么算"本站的规则"**（2026-10-05，#126）：对准旧库内部的选择器是一份**它的怪癖清单**，把等量的一份搬进新层只是把同一种脆弱重新刷一遍漆。所以每一条在删掉之前都要先问它当初守的是什么，而两类东西的处置不同：**库的补丁**随库一起死；**本站的规则**改成挂在我们自己的锚点（`data-slot`）上，这样换层之后它照样成立。#126 按这条把封面生成器标签行的三条全部改成锚点（`.cover-tabs` → `[data-slot="cover-tabs"]`、`.cover-tabs .mantine-Tabs-tab` → `[data-slot="cover-tab"]`、`.cover-tabs .mantine-Tabs-list` → `[data-slot="cover-tab-row"]`，共四条规则），它们守的都是本站的事（一排标签欠手指 46px、钉住的那一行要有自己的底色、发丝线取本站的暖色）；同一轮里**凡是读 `--mantine-color-*` 的本站规则，都改成读本站自己的属性**（`var(--site-hairline)` 这一族）——同一个模块、同一个值，中间不再隔着一个库。
  **仍然写在旧库类名上的，逐条记在这里**（#132 之后的现状）：`.touch-target.mantine-Button-root:not([data-loading])` 守的是本站的规则（命中区域要逃出裁切），但它的守卫是旧库自己的 loading 态，所以得等旧库的 `Button` 不再挂 `.touch-target` 才动——#132 之后**试点页上已经没有这样的按钮**，这一条现在只为首页与 image-converter 而活；`.format-row .mantine-Checkbox-body` / `-labelWrapper` / `-label` 与 `.mantine-Dropzone-root` 两条是 image-converter 上的本站规则，这一轮按 #111 的范围不动那一页，它们随那一页自己的迁移走。**试点页上一条都不剩**：`CoverGenerator.tsx` 里预览框那条 `border-[var(--mantine-color-default-border)]` 已改成 `border-border`（同一个值），整个文件不再 import 旧层，而 `touch-targets.mjs` 的 `no-outgoing-layer` 声明在三个分区各扫一遍 `[data-slot="tool-page"]` 之下的 `mantine-*` 类名、命中数必须是 0——所以「这一页搬完了」是被读出来的，不是被推出来的。
