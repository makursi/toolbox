# 图片资源

> **管什么**：母图与它的各份导出、工具封面、素材投递位置，以及两种明知的选择（封面与站点标记）。**和它一起读**：`apps/web/docs/design/colour.md`（无强调色的那条例外）、`apps/web/docs/design/components.md`（没有封面时卡片怎么排）。

一切都从本站源提供：CSP 只允许 `img-src 'self'` 与 `font-src 'self'`，所以远程图片或字体在这里**不是"不推荐"，而是被拦掉**（见 `docs/adr/0005-no-outbound-requests.md`）。

| 资源     | 路径                                                          | 接线位置                                                            |
| -------- | ------------------------------------------------------------- | ------------------------------------------------------------------- |
| 母图     | `apps/web/assets/brand/makursi.png`（500×500）                | 不接线：它是所有导出物的来源，留在仓里是为了下次重导时不用再找原图  |
| 标签图标 | `apps/web/src/app/icon1.png`（32×32）、`icon2.png`（128×128） | 由 Next 的图标文件约定写进 `<head>`，浏览器标签、书签与搜索结果用它 |
| 页头标记 | `apps/web/public/brand/makursi.png`（128×128）                | `SiteHeader` 里按 28px 渲染                                         |
| 主屏图标 | `apps/web/src/app/apple-icon.png`（180×180）                  | 同上，iOS「加到主屏幕」时用它                                       |
| 工具封面 | `apps/web/public/tools/<slug>/cover.jpg`                      | 该 Tool 的卡片，通过在它 `meta.ts` 里写 `cover` 生效                |

**标记是一张外部插画，不是从 wordmark 派生的字形。** 以前的规则与此相反：页头那行文字**就是** logo（因为一个 `T` 的几何字母可以由它派生），所以在没有真正的标记之前，文字是唯一诚实的选择。现在所有者交来了站点名字所指的那个角色：页头把它按 28px 显示在 wordmark 左边，两者在同一个回首页的链接里。这是**有意推翻的一条决定**，理由与取舍见 `docs/adr/0011-the-mark-is-a-supplied-illustration.md`。

**标记里有三件必须知道的事。** 一是**页头与标签页用的是同一张图导出两次**（`public/brand/makursi.png` 与 `icon2.png`）：Next 只认 `src/app` 里的图标文件，所以同一张紧裁不得不存两份——以前那对 `icon.svg` / `apple-icon.png` 也是这么来的。二是标签图标裁的是**头肩**而不是整身：16px 下整身会糊成一条棕色竖条，头肩是唯一还能读出「一个戴帽子的人」的裁法。三是 **`apple-icon.png` 有底色、没有透明通道**：iOS 把透明当黑，而角色的帽子本身就是深灰，压 ink 底会一起糊掉，所以底用暖色画布 `#f7f6f3`。它同样**不跟随明暗模式**——浏览器不告诉图标自己在什么配色的边框里。

**素材投递**：还没定稿的图放 `apps/web/assets/inbox/`（图片不进 git，只有那份 README 进），里面写了每张图要什么比例、多大、什么内容要求；处理完的正式资源才进 `public/`。

**现有封面的来源与例外。** 这张图是所有者自己截图并交给仓库的（来源记在 `apps/web/src/tools/image-converter/meta.ts` 的注释里），因此：一是它不遵守本节的暖色单色要求，二是**不做单色化处理**。我们试过把去色 + 暖色偏色的双色调版本渲染出来对比，最后选了原图：一张彩色封面会成为页面上唯一一处非语义的颜色，换来的是卡片有真实配图，这是知情的取舍。三是**它不随仓库的许可被再授权**：别人 fork 这个仓库时，不应把这张图当成可自由使用的素材，那与代码的许可无关。**站点标记（本文件开头那张母图与它的三份导出）同属这一类**：它是所有者交来的角色插画，同样不在仓库许可的范围内。

封面在 `ToolMeta` 里是**可选的**，而这个"可选"体现在版面上，不只体现在数据上：**没有封面就不渲染图框**，卡片退回纯文字排版。曾经的做法是不管有没有图都预留那个 4:3 框，代价是唯一的卡片上最显眼的位置长期是个空洞，并且那个框上的行内 `width` 把同一行的文字挤成一条竖排窄条（768px 以上都如此：Mantine 的 `sm` 是 `48em`，而那个框上的行内 `width` 压过了响应式属性，详见 `apps/web/docs/design/layout.md`）。有封面时图框照旧按 4:3 预留，图到达时不会在加载过程中跳版；无封面到有封面会让卡片由纯文字变成两列，那是一次有意的版面修改，不是跳版。**任何情况下都不放替代图形**——伪造一个 logo、或用 div 拼一张假截图，正是协议明令禁止的。`registry.test.ts` 会校验声明出来的 `cover` 是同源图片路径。
