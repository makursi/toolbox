# The instruments' rules live in the Design doc set

> **Scope**: this decision binds the **Instrument tier** — the scripts under
> `apps/web/scripts/` (`touch-targets.mjs`, `ui-fingerprint.mjs`, `cdp.mjs` and
> the pure `cdp-response.mjs`) and the module that now owns their rules,
> `apps/web/docs/design/instruments.md`. It does not reach the Gate
> (`apps/web/e2e/`, `docs/adr/0012-playwright-for-the-browser-gate.md`), the 44px
> rule (`apps/web/docs/design/components.md`), the layer order
> (`apps/web/docs/design/checklist.md`), a Tool's own rules
> (`docs/adr/0014-tool-scoped-rules-live-with-the-tool.md`), or the run
> instructions, which stay in each script's header.

The two Instruments' rules — what each one reads, how a Reading is taken, what it deliberately refuses to read, and what makes the one in CI exit 1 — were roughly 390 lines of English comments inside the scripts. A reader could not find them: the statement sat behind a 1824-line file whose first line of code was line 117, and the routing table in `apps/web/docs/design.md` had no row for the Instruments at all. The same rule was written more than once — 27 passages in the scripts had a counterpart in the docs — and the copies rotted. They are now a module of the Design doc set, `apps/web/docs/design/instruments.md`, Chinese like its siblings: one section per script (`touch-targets`, `ui-fingerprint`), one for the shared connection layer (`cdp`), and one for the reading semantics the two Instruments share. Each script keeps one pointer line at the top of its file, and a repository-level check keeps that pointer true in both directions. The glossary gained the one word the module is built on — **Reading**, in `CONTEXT.md` — and the entry gained the routing row. The migration ran one script per commit, each with a comment-only script diff, and its evidence is the Instrument's own report rather than a textual diff.

**What moved out of the comments.** Each script's **charter** — what it reads, and what it deliberately does not read: the hit-area Instrument reads hit-testing only, not the keyboard, focus order or painting, and it does not read a declaration as a hit area; the fingerprint reads our own anchors rather than a component library's class names, and reads how something is drawn rather than how big it is. Its **method** — the cases a Reading is taken on (five width × height cases, two colour schemes, and on the narrow widths a second pass under an emulated phone pointer), the state a page has to be brought to first, and what is waited for before a Reading is taken. The **exit-1 conditions** of the one that runs in CI — the module's `touch-targets` section is their one statement — and the fingerprint's own, which does not run in CI because its "before" is a file a person saved on one machine. And the **shared reading semantics**: the walk out from a control's centre, the sampling resolution that makes a 44px span read 43, the 120-step cap on each side, the rule that a hit is the control itself or anything inside it, the two pointer branches, and the stillness wait that says a Reading is taken after the page stops changing.

**What deliberately stayed in the scripts.**

- **Each Claim's own prose, beside the registry.** A Claim's `about`, its `falsification` route and the report lines only it prints stay in the script, next to `CLAIMS`: a person editing one claim reads it there, and some of those strings are data the code reads.
- **The reasons beside the functions and the lines they explain.** Unit-rationale is the largest block left in the scripts — 242 lines in `touch-targets.mjs` — and it stays on purpose: a reason beside the line it explains is what co-location is for.
- **The machine-read directives**, including the 31 comment lines that sit inside template literals, because one backtick inside one of them would end the outer template and the page-side expression would stop parsing.
- **The usage block**, including the Chrome that has to be running already: the run instructions sit where the run happens.

**The pointer, and the check that keeps it true.** A `//` comment line at the top of each of the four files, naming the module and the section that covers it (`#touch-targets`, `#ui-fingerprint`, `#cdp`): _The rules this script implements — what it reads, how a Reading is taken, what it does not read, and every exit-1 condition — are in `apps/web/docs/design/instruments.md#touch-targets`._ `scripts/check-doc-pointers.mjs` — tooling that belongs to no package, the shape `scripts/check-readme-parity.mjs` set, run as the root `pnpm check:docs` — reads both directions once per script: the pointer names a document that exists, and that document names the script's own file name. A script with no pointer line is a failure rather than a silence, so a new Instrument cannot arrive uncovered — the direction a one-way check cannot see. The anchor is deliberately not resolved: `#touch-targets` breaks on a heading rename for reasons that say nothing about whether the text is still true. Its `--falsify` injects a pointer naming a document that does not exist and a script the module does not mention, requires each injection to produce the failure it stands for, and then requires the untouched tree to come back green — in memory, writing no file, the way the hit-area Instrument's own mode does. CI runs `pnpm check:docs` and `pnpm check:docs --falsify` inside its existing docs step, whose job name changed from `readme` to `docs`; **CI still has eight steps**. There is no unit test for it, deliberately: the plan expected the predicate to be tested beside the connection layer's response classification, and a repository-level script that belongs to no package has no test runner — the precedent the README parity check sets — so its evidence is its own run, its falsification mode and that CI step. That is the one place where what shipped differs from what the ticket sketched, and it is recorded here rather than left to be noticed.

**Rejected: "the rules live in the scripts' comments and are maintained by hand."** The comments are at the point of use, which is exactly what a reason wants and exactly what a rule cannot rely on. A rule has its own reader, who arrives from the Design doc set, and a rule stated in three places is a rule with three answers to "where do I edit it". The evidence is this round's:

- **27 passages** in the scripts had a counterpart in a document that owns the meaning (`AGENTS.md`, `CONTEXT.md`, `docs/adr/`, the design modules, a Tool's `rules.md`). All but one were cut on the non-owning side in this work, not later, because duplication in this repository has already been observed to rot; the exception is the usage block, whose counterpart was a sentence pointing at it, so its resolution was to keep the usage where the run happens.
- **The layer-order sentence went stale in two places inside one script.** `touch-targets.mjs` still wrote `theme → base → mantine → components → utilities` in two comments after that layer had been deleted, and a two-axis review was the only thing that found it. It was not decoration: the falsification mode's whole argument rested on that sentence.
- **Issue #171's lesson: a record away from where a reader is looking does not get read.** The gate's font-enumeration flake was already written down in the log's unproven list for the round, and it still took five red runs before it was filed — because a log entry does not get looked at when a pull request goes red. Applied here: the rules were written down, in a file nobody opens to read a rule, and the doc set that everybody opens had no row that led to them.
- **The always-loaded copies were the worst of them.** Root `AGENTS.md` carried a version of the exit-1 list in context on every single turn, and `apps/web/AGENTS.md` carried a longer one — both caches of what the module now states.

**This reverses a split made one round earlier.** In the one-layer round (`9f01aec`, #170) the two always-loaded `AGENTS.md` files were deliberately given **different amounts of the same list**: the root file a compressed version, the package file an enumerated one. #187 removed the list from both and left one pointer in each; this ADR is why the split does not come back. Root `AGENTS.md` keeps what only it can say — what each Instrument answers; that CI runs the hit-area one, with its falsification mode, as the Hit areas step after the gate, on the build the gate already drove, with the browser the gate pinned; and that the usage of both is in each script's header comment. The package file keeps the tier paragraph and the directory paragraph. Neither carries a copy of a condition the module states.

## Consequences

- **A rule has one home.** A change to a rule is one commit touching the module and the code, which is this repository's existing rule for an owning document; a change to a record — the log — may be a doc-only commit.
- **The migration's evidence is an Instrument's report, not a diff.** The moved prose was translated rather than copied — the module is Chinese because the Design doc set is; the scripts, the pointer lines and this ADR are English because code and ADRs are — so a textual diff could not carry the claim that nothing about the measurement changed. Each script moved in its own commit with a comment-only diff (the non-comment line counts identical, `node --check` clean), and each reading that closes one is the Instrument's own: a `touch-targets` sweep and its falsification mode, and the fingerprint's capture-and-compare.
- **A reader of a script is never stranded.** The pointer is the first comment line in the file, which is what someone opening a 1824-line script is left with.
- **The documents that own other rules keep them.** The tier decision stays with ADR-0012, the 44px rule with the components module, the layer order with the checklist, a Tool's own rules with its `rules.md`, and the run instructions with the headers. The module names each of those owners rather than restating them.
- **The module's shape is the pattern for the next Instrument.** One section per script plus the shared layer, and the check fails a script with no section — so the pattern is enforced when a script lands rather than remembered.
- **Dated measurements stay in the log.** The module describes the current reading; the numbers, the runs and what is still unproven belong to `apps/web/docs/design/log.md`.

## Considered Options

- **Keep the rules in the scripts' comments, maintained by hand.** Rejected for the evidence above: 27 passages with a counterpart in the docs, the layer-order sentence stale in two places inside one script and found only by a review, and #171's lesson that a record away from where a reader is looking does not get read.
- **Move everything — a Claim's prose, every per-line reason, the directives, the usage.** Rejected: the doc set would become a second copy of the claim registry, a reason a reader needs would move to another file, and the machine-read comment lines are code — a backtick inside one breaks the template it lives in.
- **Keep the exit-1 list in both `AGENTS.md` files** (the state of one round earlier). Rejected: both were caches of what the module states, and the root one was paid for on every turn of every session.
- **Resolve the anchor in the check.** Rejected: an anchor breaks on a heading rename for reasons unrelated to whether the text is still true, so the check would fail for something that is not a finding.
- **A `--help` flag on the Instruments instead of a module.** Rejected, and out of this round's scope: usage is read where the run happens, and a rule is read by whoever is changing it — a different reader, at a different moment, in the doc set.
