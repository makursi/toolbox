## 第一部分 · 功能实现（产品内容）

### 定位

自由组合文字、图标与背景，实时预览，并导出 **1:1、4:3、16:9、21:9** 封面。界面大致分为四块：**实时预览区**、**内容面板**、**样式面板**、**导出设置**。

### 界面分区

- **实时预览区**：中央画布实时显示当前封面效果；画布左上角显示当前比例（如 `16:9`）；默认示例布局为「左侧文字 + 中间图标 + 右侧文字」（示例 · 图标 · 文本）；修改任意配置后即时刷新预览。
- **内容面板**：文本（左/右两段）、图标、背景图。
- **样式面板**：尺寸、颜色、阴影。
- **导出设置**：比例、倍率、文件名、格式、背景透明、下载。

### 功能清单（原 cg-1.md 全文并入）

#### 1. 实时预览

- 中央画布实时显示当前封面效果
- 画布左上角显示当前比例（如 `16:9`）
- 默认示例布局为「左侧文字 + 中间图标 + 右侧文字」（例如：示例 · 图标 · 文本）
- 修改任意配置后即时刷新预览

#### 2. 内容设置

**文本设置**

- **左侧文字**：可编辑（默认「示例」）
- **右侧文字**：可编辑（默认「文本」）
- **字体粗细**：滑块调节（示例显示为 400）
- **自定义字体**：支持「上传字体」
- **系统字体**：支持「获取系统字体」（依赖浏览器 Local Font Access API；不支持时会提示）

**图标设置**

- **上传图标**：可上传本地图标文件
- **显示开关**：控制图标是否显示
- **图标库搜索**：可搜索图标库（当前示例为 `lucide:image`）
- **图标背景**：可为图标单独开启背景

**背景图片**

- 支持点击或拖拽上传背景图
- 作为封面整体背景使用

#### 3. 样式设置

**尺寸设置**

- **等比缩放**开关：开启后相关尺寸联动缩放
- **字体大小**：滑块调节（示例 64px）
- **图标大小**：滑块调节（示例 64px）
- **图标圆角**：滑块调节（示例 0%）
- **间距**：文字与图标之间的间距（示例 20px）

**颜色设置**

- **颜色同步**开关：统一或分别控制颜色
- **原色图标**开关：保留图标原始颜色
- **文字颜色**：色值选择（示例 `#000000`）
- **图标颜色**：色值选择
- **背景颜色**：色值选择（示例 `#ffffff`）
- **背景不透明度**：滑块 0–100%（示例 100%）

**阴影设置**

- 作用范围可选：**全部 / 文字 / 图标**
- **阴影颜色**：可单独设置

#### 4. 导出设置

- **画板比例**：可选 **1:1、4:3、16:9、21:9**（界面显示当前为 16:9）
- **缩放倍率**：如 1x（并显示对应像素，例如 16:9 下 1x 为 `1067×600 px`）
- **文件名**：可自定义（示例「示例文本」）
- **格式**：PNG（界面可见；具体是否还有 JPG/WebP 以实际下拉为准）
- **背景透明**：开关，可导出透明背景
- **下载**：一键按当前比例下载（按钮文案示例为「下载 16:9」）

#### 5. 整体能力归纳

| 类别     | 具体能力                                                    |
| -------- | ----------------------------------------------------------- |
| 布局结构 | 左文 + 中图标 + 右文 的固定组合式布局                       |
| 文字     | 左右两段文案、字重、字号、自定义/系统字体                   |
| 图标     | 图标库搜索、本地上传、显隐、大小、圆角、原色/着色、独立背景 |
| 背景     | 纯色 + 透明度，或本地上传背景图                             |
| 样式     | 等比缩放、间距、颜色同步、阴影（全部/文字/图标）            |
| 比例     | 1:1、4:3、16:9、21:9                                        |
| 导出     | 倍率、自定义文件名、PNG、可选透明背景、一键下载             |
| 隐私     | 浏览器端操作，本地上传字体/图标/背景图                      |

#### 6. 使用特点说明

1. **结构相对固定**：核心是「左文字 + 图标 + 右文字」，不是任意多图层自由拖放编辑器。
2. **配置集中**：内容（文案/图标/背景图）与样式（尺寸/颜色/阴影）分栏，导出单独一块。
3. **本地资源友好**：支持上传字体、图标、背景图，并尝试读取系统字体。
4. **导出直接可用**：选比例与倍率后即可下载对应尺寸封面。

### 空状态与首屏

默认示例布局（「示例 · 图标 · 文本」）就是首屏——文案明写"示例"，是**显式的演示态**，不违反 `design.md`"不编造图形与数据"（编造的是假装有内容的占位图）。issue 里写明这是**有意**的，且示例文案可一键清空。

### 范围：v1 切分（cg-1 即范围："直接做 / 挂决定 / 出局"）

判据是"能诚实地宣布做完"，不是"功能齐"。

- **直接做**：四分区编辑器（预览/内容/样式/导出）· 唯一结构（左文+中图标+右文，可编辑）· 比例徽标 · 左右文字 + 字重滑块 · 背景（纯色 + 上传图 + 不透明度）· 样式全套（等比/字号/图标大小/圆角/间距/颜色同步/三色/阴影-范围+颜色）· 图标（上传/显隐/背景块）· 导出（比例四档 + 像素显示 + 1x + 背景透明[PNG 语义] + 下载按钮）· 预览 = 导出 · 纯前端无后台。
- **挂决定**（卡在第二/三部分的开放项上，每个都必须在 v1 前落地，否则从 v1 划掉）：图标库搜索的实现机制（C1）→ 第二/三部分 · 原色图标开关的语义 → 第二部分 · 导出设置区的例外边界（C3：文件名输入框 / 格式下拉 / 倍率档）→ 第三部分 · 系统字体"回退提示"文案与 Chromium-only 标注 → 第二部分 · 自定义字体上传（规格已干净，收尾实测是 acceptance）→ 第二部分 · 移动端形态 → 第二部分。
- **出局**（cg-1 没要，不用再辩护）：主题/纹理/渐变 · 平台尺寸表（事实已核验归档，备用）· 0.5–5x 倍率 · 复制到剪贴板 · 配置持久化（localStorage）· 模糊/灰度滤镜。

## 第二部分 · 技术方案与技术栈选型

### 技术栈（与仓一致）

Next.js + React + Tailwind + Mantine。状态用 React Context，放在 `src/tools/<slug>/hooks/`（本仓没有 barrel 文件、目录名等于文件名）。

### 来源项目的技术选择（背景，未照搬）

ThisCover：Next 16 + React 19 + shadcn/ui + Tailwind 4 + lucide，截图用 SnapDOM，图标搜索打 `https://api.iconify.design`，在线图源用 Unsplash API，字体从第三方 CDN（中文网字计划、ZeoSeven）取，接了 Cloudflare 统计。CoverView：CRA + `dom-to-image`，7 主题、100+ dev 图标。AcoFork 那一侧按所有者给的清单收录，未独立核实。以上每一项都要经过本仓规则重判，冲突部分见第三部分。

### 截图引擎（待选——最该写成 ADR 的一条；倾向 **canvas 2D**）

- **canvas 2D**：仓库已在用 canvas（`image-converter` 全线），编码器也在；换行/字号自适应/行高是可以被 vitest 盯住的**纯函数**（`adding-a-tool.md` §4"可测的就是纯的部分"——这恰好是此 Tool 最大的可测面）；预览与导出共用同一套 measure/draw 代码时，"所见即所得"是**构造**出来的；自定义字体在 canvas 下的用法（`FontFace(ArrayBuffer)` + `document.fonts.add` 后进 `ctx.font`）与 CSP 无冲突。代价：把中文换行写一遍。
- **SnapDOM（真身 `@zumer/snapdom`）**：MIT、`dist/snapdom.mjs` ~244 KB、活跃维护（v3.1.0 2026-09、月下载 169 万）——注意 npm 上的 `snapdom` 是 2017 年一个无关库。免费拿到"预览 = 导出"，省掉在 canvas 上重实现中文换行；代价：光栅化保真交给浏览器、244 KB 进主包、`blob:` 图片与严格 CSP（`font-src 'self'`）下的行为**无文档**（需生产构建实验）、数据字体进 SVG 序列化的 CSP 行为逐引擎存疑。旧稿引的"爱心/五角星纹理错乱" bug **查无实据**（来源项目 ThisCover 亦无法定位）→ 从证据中删除。
- 若选 SnapDOM，两个生产实验项必须立项（`blob:` 图片抓取、数据字体进 SVG 的 CSP 行为）。无论选哪个，所见即所得都是硬约束（第一部分 §1）。

### 图标机制（对应第三部分 C1 的出路；倾向 **lucide 同源 chunk**）

- **事实**：lucide `icons.json` 0.61 MB / 1853 图标；ph 4.57 MB / 9072 图标（6 字重，单字重可砍 83%）；simple-icons 4.77 MB / 3460 图标。搜 ~3000 图标的同源索引 ≈ 1–5 MB raw / ~0.3–1.5 MB gzip（估）。
- **出路 1 · 固定编译集**（沿用 `@iconify-json/ph` 编译进 CSS）+ 搜索退化为筛选器：最便宜，但**兑现不了"搜 lucide 库"**——`lucide:image` 会变成"从百来个里筛"。
- **出路 2 · lucide-only 同源 chunk**：`icons.json` 0.61 MB 整体进仓，动态 `import()`，inline SVG 渲染；搜索 = lucide 全集（1853 图标）。这是**新的图标机制**，要改 `ADR-0009` 或另开一条 ADR，但成本远低于"搜 3000 个图标"的 MB 级索引。品牌彩色集（simple-icons）未来按需加分片。
- **出路 3 · 服务器路由**：直接重开 `ADR-0005`。不推荐，但要写出来，免得它以后以"只是加个代理"的样子回来。
- **原色图标语义**（挂机制决定）：`lucide` 是单色线性图标集，"原色"对其基本无意义；"原色"只对品牌彩色集和上传图标有真实语义。倾向：**库图标单色、原色 = 上传图标专用**；若坚持库图标也要原色 → inline SVG 渲染整套 + 机制升级，v1 推迟。

### 字体（上传 + 系统字体；中文字形的答案）

- **自定义字体上传**：`new FontFace(family, ArrayBuffer)` 在**规格层面**不受 `font-src` 管辖（CSS Font Loading ED §2.1/§2.2：BufferSource 走 `[[Data]]` 内存解析、不发请求；CSP3 的 fetch 指令只拦 request；WPT font-src 套件全是 URL 型，无 BufferSource 用例）。访客上传走 `File.arrayBuffer()` **不经 fetch**，`connect-src` 也碰不到。残差：逐引擎行为（尤其 Safari）与 `FontFaceSet.add()` 是否重触发 CSP 检查 → **生产构建录一次基线**（acceptance 项，非前置阻塞）。倾向：进 v1。
- **系统字体（Local Font Access API）**：`queryLocalFonts()` 仅 Chromium 桌面（Chrome/Edge 103+、Opera 89+，全局使用率 ~30.76%）、实验性非 Baseline、要 `local-fonts` 权限 + 用户手势；WICG 已实质停滞（issue #103：TAG 批评过、spec 编辑 2025-05 退出）；CJK 枚举"设计上应包含"但**无任何测试确认过 macOS/Windows 的中文字体**，且不保证返回完整列表。∴ 在 Firefox/Safari/全 Android 上该功能**不存在**——cg-1 的「不支持时会提示」分支才是主流路径，回退文案进 `core/hints.ts`；不为它引入 polyfill。
- **中文字形**（Issue #38 第 2 点"值得故意决定"的答案）：**系统回退 + 访客自带**。文档承诺要写进 README 与 `design/typography.md`：同一份设计在两台不同系统的机器上导出，字形不一样。

### 导出管线与移动端

- **导出**：浏览器原生 `toBlob` + `<a download>`，主线程，不引入 Worker；格式固定 PNG 起步（JPG/WebP 下拉是 C3 例外区，见第三部分）；倍率只留 1x——"选比例即得对应像素"已满足"导出直接可用"，多倍率的唯一自洽理由是"同一设计出多个像素密度"，那是预设档位的事，不是开关。
- **像素上限**：v1 无倍率，最大档 21:9@2560×1080 ≈ 2.8M 像素，画布上限按此定（远低于旧稿 5x 的 39MP）。
- **移动端**：预览置顶（sticky）+ 设置分区折叠；先按 390px 设计再放宽；`≥44px` 命中区。（本仓两份 instrument 的适配见第三部分"与 Issue #38 的预期相反"。）

### 事实核验状态（2026-09 闭合一轮；剩余只有"生产构建实测"）

1. ✅ **已核验**：`FontFace(ArrayBuffer)` 规格层面不经 CSP（见上文"字体"）。残差逐引擎 → 生产构建两条路各录一次基线。
2. ✅ **已核验**：`queryLocalFonts()` 仅 Chromium 桌面、实验性、要权限、WICG 停滞、CJK 未验证、不保证完整列表。
3. ✅ **已核验**：SnapDOM 真身、许可、体积、维护状态；`blob:`/严格 CSP 行为无文档仍待实验；旧稿引的 bug 与 ThisCover 查无实据。
4. ✅ **已核验**：Iconify 三集体积（lucide 0.61 MB 可整体同源，是 C1 出路二变便宜的关键事实）。
5. ✅ **已核验（归档）**：平台尺寸表十数条——小红书 1080×1440 / 3:4、B站 1146×717 / **16:10 并非 16:9**、公众号首图 900×383 / 次图 **1:1 中心裁 ~383×383**（200×200 是旧值）、知乎 690×280、头条 16:9 ≥660、YouTube 官方口径已改为"越大越好 最高 3840×2160"（1280×720 是传统标准）、X 信息流 16:9 且"2:1 是 legacy Cards"、dev.to 1000×420、Hashnode 1200×630。cg-1 无平台概念 → **归档备用，不进本工具范围**。
6. ⚠️ **仍未实测**：大画布在目标机型上的实际内存与耗时（v1 上限 2.8M 像素，压力已降级；`AGENTS.md` 记过 `next build` 偶发死于 spawn worker 的 flake，重试一次）。

### ADR 候选

- **截图引擎**（canvas 2D vs SnapDOM）→ 一条 ADR。三个条件都满足：难逆转、无语境会问"为什么"、有真实权衡（可测性 vs 浏览器级保真）。
- **图标机制**若选"lucide 同源 chunk"→ 改 `ADR-0009` 或另开一条 ADR（新图标机制，运行期数据进浏览器，推翻"只有源码字面类名会被编译"的现状）。

## 第三部分 · 与本项目冲突

### C1 · 运行期图标搜索（三重锁；cg-1 保留搜索 ⇒ 已从"要不要"变为"必须决策"）

1. `ADR-0009`：图标是 `@iconify-json/ph` 这个 devDependency 在**构建期**读出来、编译进 CSS 的，且只有源码里**字面出现**的类名才会被编译（`icons.test.ts` 拦运行期拼出来的名字）——搜索框需要把图标**数据**放**运行期**的浏览器里。
2. `ADR-0005` + CSP：`connect-src 'self'` 拦掉 `api.iconify.design`。
3. `e2e/no-outbound-requests.spec.ts`：断言**零跨域请求 + 零 console 警告**——CSP 违规本身会在 console 报一条，那条 gate 会红。

出路与各方案的代价见**第二部分"图标机制"**；**决定必须在 v1 之前做出**。

### C2 · 中文 CDN 字体

来源项目从第三方 CDN 取字体（中文网字计划、ZeoSeven）；方案已把它改成"上传 + 系统回退"（上传规格已证实，见第二部分）——这条**已经被方案自己修掉了**，但它留下的那句话（导出图里的字形取决于导出机器）必须白纸黑字写进 README 与 `design/typography.md`，否则它会作为一个"被发现"的意外回来。

### C3 · 导出设置区的形状（原"输出设置"禁令，2026-09 已随解耦移除）

- **前提已改变（2026-09 解耦）**：`design.md` 否掉清单里那条"工具页的输出设置"全站禁令已随解耦移除，`ADR-0010` 首行也标明了作用域（只绑定 image-converter；决定见 `docs/adr/0014-tool-scoped-rules-live-with-the-tool.md`，提取与处置见 `docs/drafts/decouple-tool-rules.md`）。所以 cg-1 的导出设置区**不再撞全站规则**——它是封面生成器自己的产品决定，在 issue 里定即可，不需要给这个 Tool 写例外。
- **可操作界线**（保留为方案自己的偏好）：**构图的那一面（尺寸/文案/图标/背景/颜色/阴影）是内容，不让步；输出的那一面（格式、倍率、文件名）是输出设置，怎么给由本 Tool 决定。**
- **具体冲突点 · 自定义文件名**（保留原倾向）：仓里先例 `image-converter` 输出名由**规则**决定（`core/naming.ts`，换扩展名 + 后缀去重），界面**没有**文件名字段；cg-1 明确要输入框。倾向：**接受输入框**——封面是**命名产物**（下载按钮文案就叫「下载 16:9」），文件名是构图的一部分，与批量转换的自动命名不是一回事；输入框默认值仍由规则给，去重后缀逻辑沿用。

### 设计豁免（导出像素 vs 界面约束，两处都要写进文档）

- **文字/图标/背景颜色独立控制**：导出图的像素是访客的（`ADR-0010` 为"导出里的纯白"写过同样的豁免）；但**界面本身**受"没有强调色"约束，一排色块不能变成页面里的第二个声音。豁免写进 `apps/web/docs/design/colour.md`。
- **阴影系统**：`design.md` 否掉清单里"Tailwind 的重阴影"管的是**界面**，管不到导出图——这个区别要写进文档，否则下一个人会拿它当反例。

### 原色图标 vs 编译进 CSS 的单色图标

"保留图标原始颜色"与"mask-image 单色"不能共存；语义难点（lucide 本就单色）与机制出路见**第二部分"图标机制"**。需一次明写决定。

### 词汇："封面"与 Tool Card 封面撞车

`CONTEXT.md` 的 Tool Card 词条写着 "the only place a Tool's cover is used"。`adding-a-tool.md` 规定 Tool 自己的词不进 `CONTEXT.md`。倾向：产物在 UI 里带用途前缀（cg-1 的「下载 16:9」已是按比例命名），`CONTEXT.md` 不动。

### 与 Issue #38 的预期相反的地方

- **不会有第二个消费者 → 不要抽 Package**：cg-1 里没有"一次导出多个尺寸 + ZIP"，`zip.ts` 不会有第二个消费者；Worker 池只有在导出走 jsquash 出 WebP/AVIF 时才有第二个消费者（cg-1 未要求）。这个 Tool **很可能完全不动 `packages/*`**——写进 issue，免得接手的人去抽一个不存在的包（`adding-a-tool.md` §6 的反模式）。
- **首页网格切换与两份 instrument 是这次改动的一部分**（`design/layout.md:10`；`ui-fingerprint.mjs` 与 `touch-targets.mjs` 各加一行 `PAGES`，后者必须给 `minControls`）。另外 Issue #38 里指向 `docs/adding-a-tool.md`、`docs/design.md §3`、`docs/design.md §4` 的三个链接在 2026-09-20 的文档拆分（#43）之后全部 404。

### 仓内硬约束（`adding-a-tool.md` 要求的必须项，＋）

- **失败与限制**：背景图 / 图标文件 / 字体文件的上限与各自的拒绝文案（三处都上传），像素上限（21:9 档 2560×1080），画布最大边长。文案落纯函数层（`core/limits.ts`、`core/hints.ts`、`core/failures.ts` 的写法），浏览器的报错只进 console。
- **命名**：输出文件名的规则（`core/naming.ts` 先例）；若接受输入框，默认值仍由规则给、去重后缀沿用（见 C3）。
- **测试面**：`e2e/` 要有一条 spec 且必须见过一次红；README 有 QA checklist（哪些是 gate 盯着的，哪些只能人过）。
- **`meta.ts` 的一句话**：只讲能力，不重复"文件不离开你的设备"（那是页脚的事，一页一次）。
- **无障碍**：40+ 个控件的键盘路径、label、错误播报。仓里硬教训（`AGENTS.md` Gotchas）：`.touch-target` 盖在 Mantine 的 `Checkbox`/`Switch` 根节点上会吃掉鼠标点击而键盘照过——新控件按 `e2e/interaction.spec.ts` 的坐标点击方式验。
- **许可**：访客上传的字体与图标的版权是访客的事，要有一句话；我们自己若内置字体，只能是 OFL 之类。
