## 1. 登记：十三个发现

判据只有一条，也是这一轮存在的理由：**印出来的数字读作「没问题」，而实际什么都没量到。** 这是量具唯一不能有的失败方式。

### A. 共享连接层（两个浏览器脚本都 import 的那个模块）

| ID  | 位置                                  | 症状                                                                                                                                                          | 严重度 | 处置                                                      |
| --- | ------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------ | --------------------------------------------------------- |
| A1  | `cdp.mjs` 的响应分流与 `evaluate`     | 只带 `error`、不带 `result` 的协议级响应被当作「成功但值为空」。量具 6 秒后报「页面从未水合」，指纹脚本死在一次 JSON 解析里——正是它的头部声称已修掉的那种误诊 | 高     | 把「一条响应意味着什么」抽成纯函数，错误带方法名抛出      |
| A2  | `cdp.mjs` 首次连接                    | 「浏览器从没起来」是唯一没有人话的失败：抛的是运行时的 fetch 错误                                                                                             | 中     | 首次失败套用与「中途消失」相同的那句话（端口 + 启动命令） |
| A3  | `cdp.mjs` 的 `send` / `Page.navigate` | 导航失败与成功无法区分——全仓没有任何一处读过导航结果里的失败文本                                                                                              | 高     | 共享层拥有「这次导航成功了」                              |

### B. 指纹量具（读同一页两次的那一个）

| ID  | 位置                                       | 症状                                                                                                          | 严重度 | 处置                                       |
| --- | ------------------------------------------ | ------------------------------------------------------------------------------------------------------------- | ------ | ------------------------------------------ |
| B1  | `ui-fingerprint.mjs` 的 capture            | 从不确认页面到了。指向没起的 server 时两份 capture 都是同一个浏览器错误页，比对输出 `ALL IDENTICAL`、退出码 0 | 高     | 走共享层导航，继承它一直没有的到货确认     |
| B2  | 同文件：页面级大纲与视图循环的媒体设置顺序 | 配色只在视图循环里固定，于是每页的整页大纲继承上一页留下的状态                                                | 中     | 开页之前固定配色，而不是之后               |
| B3  | 同文件的模块类名过滤                       | 只留 8 位哈希的类；装着的组件库也发 7 位哈希，约 7% 的模块类（实测 407 中的 28）被无声丢掉                    | 中     | 按实际哈希形状保留，并把这条前提写在过滤处 |
| B4  | 同文件的比对循环                           | 以 before 文件的视图档位为准，只存在于 after 的档位永不比较                                                   | 低     | 取两份文件的并集                           |

## 3. 不改变的东西（重构的保护区）

任何处置如果让下列之一退化，就不如不做：

- `runClaim` 是唯一求值路径（证伪模式重放的是同一条守卫，不是它的拷贝）。
- claim 注册表的字段形状（`read` / `judge` / `prepare` / `per` / `only`）。
- 全部状态转移等待：水合信号、`aria-selected`、`下载 16:9` 出现——没有睡眠式同步。
- 证伪的**无层注入**技巧（`theme → base → mantine → components → utilities`，无层必胜）与三条读数（注入前绿、注入后红、撤回后绿）。
- `alive()` 只在导航前探；命令超时；**没有中途重启**。
- 阈值 43 与它的理由；case/pointer/配色三张矩阵；`.touch-target` 的 44px 规则本身。

## 6. 雾区：Tool 自己的几何 claim 该住在哪

今天量具持有封面生成器的 5 条版式 claim（两列顺序、预览封顶、标签行钉住），而 `adding-a-tool.md` 告诉新 Tool 的作者「把点名加到 `touch-targets.mjs` 里」。于是这件事是被**惯例**决定的，不是被**决定**决定的：

- ADR-0014 的 Decision 1 把「gate 与 instrument 两层」列为站点级；
- 同一个 ADR 的 Decision 2 把「Tool 的数字」判给 Tool 自己；
- 而这 5 条 claim 正好是「站点级的层，执行 Tool 的数字」。

ADR-0014 没有回答这一条，本轮也不回答（Q1）。它登记在这里，以免下一个人从一个惯例里反推出规则。可选方向（未评估、未承诺）：量具退化成引擎（视口×指针×配色循环 + 单一求值路径 + 报告 + 证伪），页面专属的 claim 与读数表达式由 `src/tools/<slug>/` 提供；代价是 Tool 专属代码进入 `src/`，`tsc` 与 oxlint 从此管它。
